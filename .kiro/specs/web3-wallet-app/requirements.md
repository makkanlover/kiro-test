# 要件定義書

## 概要

ローカル環境でスタンドアローンで動作するweb3ウォレットアプリケーションを開発します。このアプリケーションは、EVM系ネットワーク（Sepolia、Amoyテストネット）に対応し、ユーザーが暗号通貨の管理、送受信、残高確認、スマートコントラクトのデプロイと検証を安全に行えるデスクトップアプリケーションです。プライベートキーはローカルに保存され、外部サービスに依存しない自己完結型のソリューションを提供します。

## 要件

### 要件1

**ユーザーストーリー:** 暗号通貨ユーザーとして、複数の方法でウォレットに接続したい。異なる使用シナリオに応じて最適な接続方法を選択するため。

#### 受け入れ基準

1. ユーザーがアプリケーションを開始した時、システムは3つの接続オプションを表示する：「新しいウォレットを作成」「ローカルウォレット」「外部ウォレット接続」
2. ユーザーが接続方法を選択した時、システムは選択された方法に応じた適切なインターフェースを表示する
3. 接続が成功した時、システムは現在の接続方法とウォレットアドレスを表示する
4. 接続方法が変更された時、システムは新しい接続に応じてUIを更新する

### 要件2

**ユーザーストーリー:** 暗号通貨ユーザーとして、新しいウォレットをローカルで作成したい。外部サービスに依存せずに暗号通貨を安全に保存・管理するため。

#### 受け入れ基準

1. ユーザーが「新しいウォレットを作成」をクリックした時、システムは新しい秘密鍵と公開アドレスのペアを生成する
2. ウォレットが作成された時、システムはバックアップ用の12単語のニーモニックフレーズを表示する
3. ウォレット作成が完了した時、システムはユーザーが提供したパスワードで秘密鍵を暗号化してローカルに保存する
4. ユーザーがパスワードなしでウォレットを作成しようとした場合、システムは最低8文字のパスワード入力を要求する

### 要件3

**ユーザーストーリー:** 開発者として、ローカルの環境変数ファイルから秘密鍵を読み込みたい。開発環境で簡単にウォレットを使用するため。

#### 受け入れ基準

1. ユーザーが「ローカルウォレット」を選択した時、システムは.envファイルの場所を指定するオプションを提供する
2. .envファイルが選択された時、システムはPRIVATE_KEY変数を読み込む
3. 有効な秘密鍵が見つかった時、システムは対応するウォレットアドレスを表示する
4. .envファイルが見つからないまたは無効な場合、システムは明確なエラーメッセージを表示する
5. 秘密鍵が正常に読み込まれた時、システムはウォレット機能を有効にする

### 要件4

**ユーザーストーリー:** ユーザーとして、MetaMaskウォレットを接続したい。既存のMetaMaskアカウントを使用してアプリケーションを利用するため。

#### 受け入れ基準

1. ユーザーが「MetaMask接続」を選択した時、システムはMetaMaskの接続を要求する
2. MetaMaskが利用可能な時、システムはアカウント接続の許可を求める
3. ユーザーがMetaMaskで接続を承認した時、システムは接続されたアカウントアドレスを表示する
4. MetaMaskがインストールされていない場合、システムはインストールガイドを表示する
5. 接続が成功した時、システムはMetaMaskを通じてトランザクション署名を行う

### 要件5

**ユーザーストーリー:** ユーザーとして、WalletConnectを使用してモバイルウォレットを接続したい。モバイルデバイス上のウォレットアプリを使用するため。

#### 受け入れ基準

1. ユーザーが「WalletConnect接続」を選択した時、システムはQRコードを表示する
2. QRコードが表示された時、システムは接続手順の説明を提供する
3. モバイルウォレットでQRコードがスキャンされた時、システムは接続要求を処理する
4. ウォレットアプリで接続が承認された時、システムは接続されたアカウント情報を表示する
5. 接続が確立された時、システムはWalletConnectプロトコルを通じてトランザクション要求を送信する

### 要件6

**ユーザーストーリー:** ウォレットユーザーとして、暗号通貨の残高を確認したい。異なるトークンの保有状況を監視するため。

#### 受け入れ基準

1. ウォレットがアンロックされた時、システムはサポートされている暗号通貨の現在の残高を表示する
2. 残高が表示された時、システムはトークン量と法定通貨相当額の両方を表示する
3. ユーザーが残高を更新した時、システムはブロックチェーンネットワークに最新情報を問い合わせる
4. ネットワーク接続が失敗した場合、システムはタイムスタンプ付きの最後の既知残高を表示する
5. 複数のトークンを保有している時、システムは整理されたリスト形式で表示する

### 要件7

**ユーザーストーリー:** ウォレットユーザーとして、他のアドレスに暗号通貨を送信したい。支払いや送金を行うため。

#### 受け入れ基準

1. ユーザーが送信トランザクションを開始した時、システムは受信者アドレスと金額の入力を要求する
2. トランザクション詳細が入力された時、システムは推定ガス手数料を計算して表示する
3. ユーザーがトランザクションを確認した時、システムはパスワード認証を要求する
4. トランザクションが署名された時、システムは適切なブロックチェーンネットワークにブロードキャストする
5. 残高が不足している場合、システムはトランザクションを防止してエラーメッセージを表示する
6. トランザクションが送信された時、システムはトランザクションハッシュとステータスを表示する

### 要件8

**ユーザーストーリー:** ウォレットユーザーとして、暗号通貨を受信したい。他の人から支払いを受け取るため。

#### 受け入れ基準

1. ユーザーが「受信」を選択した時、システムはウォレットアドレスをテキストとQRコードで表示する
2. アドレスが表示された時、システムはクリップボードにコピーする機能を提供する
3. QRコードが生成された時、システムはスキャン可能な形式でウォレットアドレスを含める
4. ユーザーがアドレスを共有する時、システムは選択されたネットワークに対して正しいアドレス形式を保証する

### 要件9

**ユーザーストーリー:** セキュリティを重視するユーザーとして、ウォレットをパスワードで保護したい。権限のないユーザーが資金にアクセスできないようにするため。

#### 受け入れ基準

1. アプリケーションが開始された時、システムはウォレットのアンロックにパスワードを要求する
2. 間違ったパスワードが入力された時、システムはエラーを表示してアクセスを防ぐ
3. ウォレットが15分間アイドル状態の時、システムは自動的にウォレットをロックする
4. ユーザーが手動でウォレットをロックした時、システムは次回アクセス時に即座にパスワードを要求する
5. ユーザーがパスワードを忘れた場合、システムはニーモニックフレーズを使用したウォレット復旧オプションを提供する

### 要件10

**ユーザーストーリー:** ウォレットユーザーとして、取引履歴を確認したい。暗号通貨の活動を追跡するため。

#### 受け入れ基準

1. ユーザーが取引履歴を開いた時、システムは全ての取引の時系列リストを表示する
2. 取引が表示された時、システムは日付、金額、受信者/送信者、ステータスを表示する
3. ユーザーが取引をクリックした時、システムは詳細な取引情報を表示する
4. 取引リストが長い時、システムはページネーションまたはスクロールを実装する
5. 取引データが利用できない場合、システムは読み込み中またはエラー状態を示す

### 要件11

**ユーザーストーリー:** ウォレットユーザーとして、ウォレットをバックアップしたい。アプリケーションへのアクセスを失った場合に資金を復旧するため。

#### 受け入れ基準

1. ユーザーがバックアップオプションを選択した時、システムはニーモニックフレーズを安全に表示する
2. バックアップが開始された時、システムはパスワード確認を要求する
3. ニーモニックが表示された時、システムはセキュリティの重要性についてユーザーに警告する
4. ユーザーがバックアップ完了を確認した時、システムはニーモニックフレーズを非表示にする
5. バックアップファイルのエクスポートが要求された場合、システムは暗号化されたバックアップファイルを作成する

### 要件12

**ユーザーストーリー:** 開発者として、EVMネットワークにスマートコントラクトをデプロイしたい。分散アプリケーションをテストおよびデプロイするため。

#### 受け入れ基準

1. ユーザーが「コントラクトをデプロイ」を選択した時、システムはコントラクトバイトコードとコンストラクタパラメータの入力インターフェースを提供する
2. コントラクトデプロイが開始された時、システムはガスコストを推定してユーザーに表示する
3. ユーザーがデプロイを確認した時、システムは選択されたネットワーク（SepoliaまたはAmoy）にデプロイトランザクションを署名してブロードキャストする
4. デプロイが成功した時、システムはコントラクトアドレスとトランザクションハッシュを表示する
5. デプロイが失敗した場合、システムは詳細なエラーメッセージと理由を表示する
6. コントラクトがデプロイされた時、システムは将来の参照のためにコントラクト情報をローカルに保存する

### 要件13

**ユーザーストーリー:** 開発者として、デプロイされたスマートコントラクトを検証したい。コントラクトのソースコードを公開して信頼性を確保するため。

#### 受け入れ基準

1. ユーザーが「コントラクトを検証」を選択した時、システムはコントラクトアドレス、ソースコード、コンパイラ設定を要求する
2. 検証が開始された時、システムは指定された設定でソースコードをコンパイルする
3. コンパイルされたバイトコードがデプロイされたバイトコードと一致した時、システムはブロックエクスプローラーAPIに検証を送信する
4. 検証が成功した時、システムは確認と検証ステータスを表示する
5. 検証が失敗した場合、システムは具体的なエラーメッセージと提案を表示する
6. コントラクトが検証された時、システムは検証ステータスでローカルのコントラクト記録を更新する

### 要件14

**ユーザーストーリー:** ウォレットユーザーとして、異なるEVMネットワーク間を切り替えたい。異なるテストネット上のコントラクトやトークンと相互作用するため。

#### 受け入れ基準

1. ユーザーがネットワークセレクターを開いた時、システムは利用可能なネットワーク（Sepolia、Amoy）を表示する
2. ユーザーが異なるネットワークを選択した時、システムはRPC接続を更新して現在のネットワークを表示する
3. ネットワークが切り替えられた時、システムは新しいネットワークの残高と取引履歴を更新する
4. ネットワーク接続が失敗した時、システムはエラーを表示して再試行またはネットワーク切り替えを許可する
5. ユーザーがトランザクションを実行する場合、システムは現在選択されているネットワークにトランザクションが送信されることを保証する
